The WebSocket transport now dials ``/tls/sni/<name>/ws`` addresses: the socket connects to the host before ``/tls``, and ``<name>`` is the TLS server name and the ``Host`` header of the WebSocket upgrade, on direct and SOCKS proxy dials, as in go-libp2p and js-libp2p. Such an address used to fail in ``can_dial`` with ``AttributeError: 'Protocol' object has no attribute 'value'``, and the dial path ignored the name, so a peer behind a TLS-terminating proxy that routes by name (a CDN edge, a tunnel) could not be reached by an address plus a name.
